收支隨手登錄｜GitHub Pages 版

檔案
index.html、styles.css、parser.js、app.js 四個檔案放在同一層。
已接上你提供的支出 Google 表單與 11 個 entry 欄位。
代收墊單選：空白／潘／黃／張／吳／lab；空白送出空值。
收入可手動填含稅總額與其中稅額，支出填未稅金額、稅额與總額；同筆只能選收入或支出。
收入收付訖為 V 收訖／空白未收，支出為 C 付訖／空白未付。
不拍照片也可以直接手動填。尚未開發票或暫無憑證，選「未開發票／暫無憑證」，匯入後再補齊。
稅額不自動猜測；無稅填 0，有稅填已確認稅額。

部署到 GitHub Pages
1. 建立新的專案（例如 expense-receipts），避免覆蓋原庫存表單專案。
2. Add file → Upload files，將上述四個檔案上傳至專案最外層並 Commit。
3. Settings → Pages → Source 選 Deploy from a branch；Branch 選 main、資料夾 /（root），按 Save。
4. 等 GitHub 顯示網址，使用手機 Safari 或 Chrome 開啟。
5. 若更新後仍見舊畫面，重新整理；電腦按 Ctrl+F5。
程式不用 API 金鑰或付費 OCR 服務。首次辨識需連網下載繁體中文及英文模型，以後速度視瀏覽器快取與手機效能而定。

使用流程
1. 按拍照或選相簿，照片方向不對可旋轉。
2. 按辨識照片。辨識後確認日期、發票／收據、未稅支出、稅與總額；項目可自己填。
3. 發票必須填正確號碼。辨識不到號碼不會自動當成收據。
4. 收據只有總額、沒有稅額時，不猜 5%。你確認無稅後，可勾「我確認這張收據無稅」。
5. 填業、收付狀態、備註、代收墊。C 付訖需另填實際收付日；未付留空白。
6. 勾「我已核對」，送到 Google 表單。
7. 查看下方 Google 回覆，看到「已記錄您的回覆」才算已確認；頁面載入不代表成功。
8. 若 Google 阻擋內嵌提交，可用「開啟預填表單」，到 Google 頁確認並提交。
9. 確認失敗後，可按「未成功，允許重送」。同一憑證ID保持不變，財務匯入會去重。
10. 完成後按清空新增下一筆。只是在畫面清空，不會刪除 Google 資料。

照片
照片在手機瀏覽器內辨識，不隨文字送往 Google 表單，也不存進 GitHub。
使用拍照按鈕不保證手機自動存到相簿；需保留時可按「下載原照片」，或先用手機相機拍好再選相簿。
辨識失敗仍可手填；也可貼入手機 OCR 文字後按「從文字預填欄位」。

如何匯入財務
方式一：Google 表單的回應試算表 → 檔案 → 下載 → Microsoft Excel（.xlsx）。
方式二：拍照頁按「下載本筆 CSV」，不用等 Google 表單即可匯入。
使用財務 v1.63：「整理與設定」→「手機收支匯入」，選檔、填來源與帳本年度，預覽後勾選新增。
同一筆憑證若用兩種方式都匯入，會依同一個憑證ID防止重複；同年度相同發票號碼另提示核對。
分類／財務性質保持待整理，之後在批次整理填。

表單欄位維持原樣
為不增加表單題目，系統會把【憑證ID:...】【總額:...】【收付日:...】放在備註末尾。
它們是系統追蹤資料；你填的備註保留在前面。
匯入財務時，收付日存入實際收付日，識別碼存入去重紀錄，備註欄恢復你填的文字。
請不要在 Google 試算表刪除追蹤標記。
直接從原 Google 表單手填時，未付可匯入；付訖的資料請在備註加【收付日:2026-10-05】這種標記，或改從拍照頁填收付日。

測試範圍
已核對公開表單題目與 entry，測試 OCR 引擎、辨識文字解析、單選值、送出欄位組裝、確認與錯誤提示及財務匯入。
沒有替你向真實 Google 表單提交測試資料；第一次使用請確認 Google 回應試算表確實新增。
尚未在你的手機上測試實際紙本發票。OCR 結果一律人工確認。

OCR 關鍵字規則
內建：看到「中華郵政」→ 項目「郵寄資費」。
在頁面下方填關鍵字、欄位、內容，按新增規則。支援項目、業、幣別、備註。
關鍵字不分英文字母大小寫，全形文字先正規化；中文需包含完整關鍵字。
只有欄位空白時才預填，保留手動內容；同一欄遇到不同結果會提示、留空讓你決定。
規則在「辨識照片」或「從文字預填欄位」時套用，收入採手動登錄。
規則只存在此裝置、此網站的瀏覽器；可匯出 JSON 再到別台匯入，匯入會先確認後取代目前規則。
若瀏覽器阻擋保存，畫面會提示，請匯出備份。
收入例：含稅實收 1,050、銷項稅 50 → 總額填 1,050、稅額填 50，銀行收入為 1,050。
手機頁仍需連網送出 Google 表單；電腦財務程式不需開機。未送出的欄位不保證關閉網頁後保留。
